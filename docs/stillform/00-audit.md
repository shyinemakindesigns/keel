# STILLFORM: Phase 0 audit

Audit of Keel v1 (merged to `main` as `c8f1b5b`) before the STILLFORM upgrade. Written October 8, 2026.

## 1. Existing architecture

| Area | Current state |
| --- | --- |
| Framework | None. Two static HTML pages, vanilla JS, no build step, no package manager |
| Pages | `index.html` (case study, 9 sections), `prototype.html` (8 screens, hash-free in-page router with `?screen=` and `postMessage` control) |
| Styles | `assets/tokens.css` (shared tokens) plus a `<style>` block per page |
| Animation | lottie-web 5.12.2 (vendored). One Lottie file, `keel-settle.json`, generated by `source/gen_lottie.py`. CSS transitions for screens and sheets. A JS spring for the keel depth |
| Rive | None |
| Data | In-memory sample state in `prototype.html`: balance, 6 bills, payday, 11 transactions, 1 goal |
| Tooling | `source/contrast_audit.py`, `source/weight_check.py` (Pillow), headless Chrome for verification |
| Dependencies | One: lottie-web. Fonts from Google Fonts |

**Decision: keep the static, no-build architecture.** The STILLFORM brief says not to migrate frameworks without a compelling reason. Nothing in the brief needs React or a bundler: every deliverable is reachable with HTML, CSS, SVG, lottie-web and the Rive web runtime. Adding a build step would make the portfolio harder to host and inspect, which works against its purpose.

## 2. What already works and stays

- The reading model (`reading()` in `prototype.html`): transparent, explainable, computed live. This is exactly the “transparent and explainable calculation” the brief asks for in the Steadiness View, so it is reused as the engine for the Steadiness View, the planning screen and the Equilibrium Indicator
- Onboarding flow, purchase check, activity filtering, transaction sheet, goal contribution preview
- All accessibility features: `role="switch"`, focus management on screen change, live regions, sheet focus return and Escape, reduced motion
- The research review, define section, IA, wireframes, testing plan and reflection. Content is preserved and re-sequenced into the 13-section structure, not rewritten from scratch
- The audit scripts. They get updated to the new palette, not replaced

## 3. Design system assessment

- Tokens exist but are flat: there are no semantic roles (action, hover, focus, disabled, info, success, warning, error, data) and no dark theme
- Three radii, three durations, two easings. Enough for v1, too thin for a documented system
- No spacing scale; spacing is ad hoc per component
- Components are duplicated between the two pages (buttons, chips, panels) with small drifts

## 4. Visual inconsistencies found

- Button and chip styles are defined twice with slightly different sizes (`index.html` 44px buttons, `prototype.html` 52px)
- The Activity screen measures 52/48/0, over on surface (already documented in v1)
- Hairline alpha is used in three different strengths inline instead of via tokens in the IA diagram and wireframes

## 5. Motion opportunities

- Category weight bar, transaction rows and goal fill change instantly or with a simple ease; none of them explain *what changed*
- No confirmation motion after categorizing a transaction (there is no categorizing yet)
- No empty state anywhere
- No continuity between Activity and the transaction detail
- The keel reading is the only physically animated object, which is correct, but its spring has a small overshoot that conflicts with STILLFORM’s “avoid excessive springs, no unnecessary bouncing”

## 6. Accessibility issues

- No dark mode, so no user-selectable contrast preference beyond the OS
- Category colors are distinguished by tint only; legends carry labels, but the weight bar itself has no text equivalent (it is `aria-hidden`). Needs a data table or summary
- The keel visualization has a `desc` but no tabular equivalent of the calculation
- The embedded prototype iframe in the case study is fixed at 390x844 scaled; at 200% zoom the side walkthrough wraps under it correctly, but this should be retested

## 7. Conflicts between the v1 brief and the STILLFORM brief, and how I resolved them

| Topic | v1 brief | STILLFORM brief | Resolution |
| --- | --- | --- | --- |
| Accent | `#E05A3A` to `#E8663F` range | Oxidized Ember `#B94F36` | STILLFORM wins: it is the latest instruction and names exact tokens. Accessible variants added where the hex fails (below) |
| Type | Fraunces + Archivo | Instrument Serif + Satoshi + IBM Plex Mono | **On hold.** The follow-up color brief (“color system refinement, not a redesign… do not change typography”) supersedes this for now. Fraunces and Archivo stay until a type change is explicitly requested again |
| Keel motion | Damped spring, one small overshoot, ~900ms | Avoid excessive springs and bouncing; chart updates 350 to 550ms | Spring becomes critically damped (no overshoot) and settles in about 520ms. The “settle, don’t startle” argument still holds, with tighter numbers |
| Second accent hue | Forbidden | Semantic success, warning, error tokens required | Semantic colors are added for status only, always paired with text or an icon, never used decoratively. The brand still has one accent |
| Headline | “Know you’re okay before you know the details.” | “Feel steady with your money.” | STILLFORM wins. v1 headline kept in the case study’s wireframe-to-final history |
| Tagline | none | “Money moves. You stay steady.” | Adopted |

## 11. Known limits, stated up front

- **Rive authoring is not available here.** A `.riv` file is produced in the Rive editor. I will build the vector assets, the state machine specification with exact input names, a working web implementation driven by the same inputs, and a loader that switches to the Rive runtime automatically when the `.riv` is added. Nothing will be labeled a Rive file that isn’t one
- **No ffmpeg.** Video will be attempted through headless Chrome’s `MediaRecorder` on a canvas Lottie render. If MP4 recording isn’t supported by the installed Chrome, the launch assets ship as working motion compositions with export instructions, labeled as such
- **3D is drawn, not rendered.** The Equilibrium Object is built in SVG with shaded gradients for a matte ceramic look, so it can be animated by Lottie, themed, and stay small. No WebGL, because nothing in the product needs real-time 3D
